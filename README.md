# 重点 ETF 资金看板

[打开宽基看板](https://risingwen.github.io/etf-fund-flow-board/) · [主题与杠杆资金](https://risingwen.github.io/etf-fund-flow-board/markets.html) · [部署和定时更新记录](https://github.com/risingwen/etf-fund-flow-board/actions/workflows/pages.yml)

公开静态看板，跟踪 20 只宽基 ETF 的分钟成交、日度申赎和净流入超过 100 亿元的历史交易日。站点部署到 GitHub Pages，图表库随站点提供，行情和历史更新使用公开数据接口。

## 数据怎样更新

| 模块 | 数据来源与计算 | 更新方式 |
| --- | --- | --- |
| 盘中行情及成交排名 | 腾讯证券五日分时，按 20 只 ETF 与上证综指共同有数据的最后一分钟对齐。单只涨跌幅按当日价格和昨收计算。09:31 包含开盘集合竞价，剔除 15:00 后的盘后成交 | 打开页面时读取。北京时间周一至周五交易时段，每 60 秒刷新可见页面。失败时继续显示上一次成功行情，页面标出行情日期 |
| 历史分钟对比 | 通达信 1 分钟 K 线的成交额回补，后续按日归档腾讯分时。归档前逐只与东方财富日线成交额核对 | 每次定时补数同时更新。任选交易日，以该日之前连续 20 个交易日的同时刻累计成交额计算均线 |
| 日度资金、托底日 | 保留上游历史，2026-10-23 之后使用东方财富日线成交额、基金单位净值、沪深交易所 ETF 份额。逐只计算相邻交易日份额差乘当日单位净值。20 只全部齐备才追加 | GitHub Actions 计划每天北京时间 08:50、16:10、20:50 补齐至前一自然日，节假日无新交易日便跳过。实际运行时间以 Actions 为准 |
| 全市场 12 类宽基 | 上交所基金目录的标的指数、深交所 ETF 目录的拟合指数按规则精确匹配。自 2026-10-26 起将每只 ETF 的相邻交易日交易所份额差乘以当日单位净值，单位为亿元 | 与日度资金同一计划更新。首页展示最新覆盖数、最近 22 个交易日及各日合计 |
| 典型日内走势 | 上游历史样本 | 展示各自的样本日期 |

页面中的成交额和净流入均以亿元计。净流入为申赎估算，“托底日”为金额阈值筛选。部分数据商会修订历史数据；日度和宽基每次重查最近三个交易日，逐券档案重查相邻份额窗口，两融重查最近十个自然日。更早的修订会由重叠窗口对账和异常检测暴露，但不保证能自动发现所有上游错误。

## 历史分钟对比

[打开历史分钟图](https://risingwen.github.io/etf-fund-flow-board/#minute-history)。初次回补覆盖 2026-06-24 至 2026-11-06，共 92 个完整交易日。以当前 20 只 ETF 回溯，每日从 09:31 至 15:00 共 240 个交易分钟。最早的 20 个日期可以查看当日曲线，从 07-22 起同时显示前 20 日均线。选择历史日期只切换这张图，图例可叠加最新行情。上方指标和成分排名始终跟随最新行情。

脚本 **`pipeline/update_minute_history.py`** 的常用命令如下。

| 命令 | 用途 |
| --- | --- |
| `py pipeline/update_minute_history.py` | 将腾讯五日分时与上证交易日历对齐，逐只核对 15:00 累计额与日线成交额后追加。北京时间 15:15 以后才允许把当天纳入归档。 |
| `py pipeline/update_minute_history.py --verify-latest` | 用腾讯和日线独立复核最近一个归档日，报告收盘和盘中差异。 |
| `py -m pip install eltdx==3.3.5`，随后运行 `py pipeline/update_minute_history.py --backfill` | 分页读取通达信分钟 K 线，用于初次建档或停更超过腾讯窗口时补缺；可通过环境变量 `TDX_HOST` 指定行情服务器。 |

脚本将逐分钟成交额累计后加总为亿元。只有 20 只基金各有 240 个有效分钟、且收盘累计额通过逐只日线校验才写入。遇到窗口缺口会停止本次写入，待数据补齐后再续接。公开接口实际保留的历史会滚动变化。

页面可见时每 60 秒检查历史数据发布版本，切回标签页或网络恢复时立即检查。发现新版本后同步更新日度图表、宽基热力表和历史分钟归档，保留所选日期、图表缩放和滚动位置。部署时由脚本 **`pipeline/build_history_manifest.py`** 生成校验清单；文件校验齐全才切换画面，失败后自动重试。旧版本页面首次需要重新打开一次以加载这项功能。

## 11 月 4 日的成交额对账

2026-11-04 的 20 只 ETF，东方财富未复权日线的实际成交额合计 **1,303.4013 亿元**。把每只 ETF 的全天成交量（手）乘以 100 份，再乘当日收盘价，得到 **1,339.3837 亿元**。后一算法复现了对照看板显示的 1,339.38 亿元，和实际成交额相差 **35.9825 亿元**。当天全部 20 只的收盘价都高于按成交金额、成交份额计算的全天均价。单只差额最大的三项是 588000、159915 和 512100。腾讯分时 15:00 的累计额提供第二个核对值。每只 ETF 两个行情源的实际成交额差异均小于 210 元。

[下载 20 只基金的逐只对账 CSV](site/audit/turnover-2026-11-04.csv)。复算脚本为 `pipeline/audit_turnover.py`，示例为 `py pipeline/audit_turnover.py 2026-11-04 turnover.csv`。新输出中的腾讯列只在对应交易日尚处五日分时窗口时可用，原始核对结果随站保存。

## 12 类宽基的覆盖

增量管线先读取[上交所基金目录](https://etf.sse.com.cn/fundlist/)和[深交所 ETF 目录](https://fund.szse.cn/marketdata/etf/index.html)，再按[指数名称或代码](reference/data/broad_benchmarks.json)匹配分类。跟踪同一指数的新增 ETF 随目录自动纳入。其他宽基采用明确列出的境内股票宽基指数，新出现的跟踪指数需要审核后加入规则。[基金清单](reference/data/broad_members.csv)记录代码、跟踪指数、分类和上市日期。首次更新以当时可核实的交易所目录回溯，2026-11-05 匹配到 379 只。

份额取交易所披露数据，单位净值取东方财富历史净值。首个上市日没有可比的上一交易日，下一交易日起计。最近 5 天内的份额或变动基金净值尚未披露齐全时，补数停在最后一个完整交易日，下次运行续补；分钟归档继续执行。缺口超过该期限、接口异常或既有基金分类消失时，任务报错。上游快照保留至 2026-10-23，含 193 个交易日；当时使用收盘价口径。区间累计线在原快照累计值上接续新口径，跨口径比较时请同时查看分界日期。

宽基脚本 **`pipeline/update_broad.py`** 沿用下面的 Python 依赖。`py pipeline/update_broad.py` 补到北京时间昨天，`--through 2026-11-05` 可限制结束日期。`py pipeline/update_broad.py --verify-latest` 从原始公开源复算末日全部分类与累计额，仅校验。日常统一流程通过逐券档案与分类汇总复算进行交叉校验。

## 发布和预览

在仓库 **Settings → Pages → Source** 选择 **GitHub Actions**。站点和静态资源均从 `site/` 发布。推送到 `main` 会自动部署。手动补数可在 **Actions → Validate, update and publish ETF board → Run workflow** 运行，勾选补数选项。定时更新如遇上游错误，查看 update 步骤日志并重新运行。

本地预览命令（在仓库根目录执行）：

```powershell
py pipeline/build_history_manifest.py
py -m http.server 8000 --bind 127.0.0.1 --directory site
```

打开 <http://127.0.0.1:8000/>。在 Linux/macOS 上将 `py` 换为 `python3`。

增量脚本 **`pipeline/update_daily.py`** 可手动运行：

```powershell
py -m pip install requests openpyxl
py pipeline/update_daily.py
```

脚本从已发布日开始核对交易日历，分批查询交易所份额和当日净值，完整数据写入 `site/data.js`。重复运行会从最后一天续跑。分钟快照脚本 **`pipeline/update_snapshot.mjs`** 使用同一套前端行情计算逻辑，在 Node.js 22 或以上运行 `node pipeline/update_snapshot.mjs` 即可更新内置分钟快照，供实时接口不可用时展示。盘中行情由打开的页面直接读取；统一定时任务只更新日终归档。复核后提交并推送即可发布。原仓库的全量研究管线和可选 Supabase 工具仍在 `pipeline/`、`deploy/` 和 `supabase/`，日常更新使用上述增量脚本。

本项目 fork 自 [sina-west4angle/etf-fund-flow-board](https://github.com/sina-west4angle/etf-fund-flow-board)。Apache ECharts 5.5.1 随站点分发，许可文件见 `site/vendor/echarts/`。

## 发布前校验与 ETF 研究

入口：[ETF 资金研究](https://risingwen.github.io/etf-fund-flow-board/research.html)。收录 379 只宽基和 213 只主题 ETF，合计 592 只；初次逐券日度回补自 2026-10-15 起，随后增量保留最近 260 个交易日。支持 1/3/5/10/20 交易日净申赎与融资净买入排名、13 类主题净申赎热力表、逐只份额/净值/规模/成交额/收盘折溢价，以及同跟踪指数的管理费和托管费比较。两融明细仍限四类宽基中有公开记录的标的。行业/概念增加多窗口融资快照，自首次采集起最多保留 22 个归档日。

脚本 **`pipeline/refresh_all.py`** 是定时更新入口；**`pipeline/data_quality.py`** 是每次推送和定时部署必须通过的门禁。检查：日期唯一及递增、精确成分集合、完整时间轴、有限数值与单位、规模=份额×净值、净申赎复算、融资买入−偿还=净买入、20 只及 12 类宽基逐券对账、日线与分时成交额一致、两融最新日与沪深交易所逐只核对。任何未知净值大幅跳变也会暂停发布候选，核实拆分、分红或单位后再处理。

文件级 SHA-256 绑定本次校验记录，数据被修改但未重新校验时禁止发布。`site/data-quality.json` 公开各模块数据日期、预期交易日、覆盖校验数量、失败原因与有效文件哈希。三个页面均展示健康状态，区分源站失败、校验失败、等待披露与逾期；超过 36 小时没有完成检查会显示心跳超时。GitHub 计划任务不保证准点，实际时间以 Actions 为准。

基金日行情缺失时收盘价和成交额留空；净值缺失时规模和折溢价留空。只有交易所确认相邻两日份额完全不变，才可在缺少净值时确定净申赎为零。份额变动且缺少净值会阻断候选。基金费率空值不等于免费，同指数比较采用公开资料的跟踪标的名称，仅限本看板收录范围。

已核实的份额事件记录在 `reference/data/fund_actions.json`。512220 在 2026-11-05 日终按 1:3 拆分，次日行情除权。净申赎用“当日份额−前日份额×3”计算；登记日收盘价除以 3 后与拆分净值比较。该日若忽略拆分会把约 +3.6684 亿元当作净申购，修正后约为 −0.0412 亿元。公告来源和调整说明在单基金页面可见。未知事件不会自动猜比例放行。

交易所目录正常刷新；源站临时失败可使用不超过 3 天的已核实目录并提示目录日期，更老则拒绝刷新相关数据。沪市指数名称只去空白字符，不截断带空格的完整指数名。公开日线主源失败时使用通达信真实成交额，绝不使用成交量乘收盘价替代。
